## 一、系统构成

```text
Android App（React + Zustand + rspack + Capacitor）
        │  HTTPS 8443
        ▼
Caddy（TLS 终结，反代到 127.0.0.1:8787）
        │
        ▼
网关 ds-gateway（Node 22，直接跑 .ts）
        ├── 鉴权：账号/会话令牌/scrypt/邮箱验证码
        ├── 代理：转发到 api.deepseek.com（只透传 4 个头）
        ├── 记忆：每用户一个 memory.db（FTS5 trigram + 向量 + RRF + 重排）
        ├── 存储：会话/附件云端同步（auth.db + users/<id>/files）
        ├── 用量：账本 usage_events（人民币峰谷价、每日配额）
        └── 更新：/update/manifest + /update/file（zstd 增量补丁）
```

服务器：阿里云 ECS `59.110.64.118`（2C2G，40G 盘）
关键路径：

```text
/opt/ds-gateway              代码 + node_modules（含 ip2region 47MB）
/etc/ds-gateway.env          环境变量（600 root:root）
/var/lib/ds-gateway/auth.db  账号/会话/用量/审计
/var/lib/ds-gateway/users/<id>/memory.db   每用户记忆
/var/lib/ds-gateway/users/<id>/files/      附件原件
/opt/ds-gateway/updates      更新包与补丁 + manifest.json
/var/backups/ds-gateway      本地备份（保留 14 份）
```

## 二、发版流程（每次都要走）

```powershell
# 1) 开发版：改代码 → 升字母版本 → 推送（每次改动都推）
"1.0.16A-debug" | Set-Content VERSION -NoNewline
pwsh -File scripts/sync.ps1 -Message "feat: 做了什么"

# 2) 出包验证
pwsh -File scripts/build.ps1        # 产物在 delivery/

# 3) 发正式版：合并到 main，版本号去掉字母与 -debug
git checkout main && git merge dev --no-ff
"1.0.16" | Set-Content VERSION -NoNewline
pwsh -File scripts/build.ps1        # assembleRelease
git tag -a v1.0.16 -m "..." && git push origin main --tags

# 4) 发布到更新通道（关键：不发布的话 App 检查不到）
scp delivery/freedeepseek-v1.0.16.apk root@59.110.64.118:/tmp/new.apk
ssh root@59.110.64.118 "cd /opt/ds-gateway && node scripts/publish-update.mjs \
  --apk /tmp/new.apk --version 1.0.16 --channel release --notes '本次更新内容'"

# 5) 必要时邮件发安装包
```

**`--notes` 会直接显示在 App 的更新弹窗里**，写给用户看，不要写内部术语。

版本号规则：`major.minor.patch[字母]-debug`；发版 = 去掉字母与 `-debug`。
`versionCode` 由版本号推导（`major*1e6 + minor*1e4 + patch*100 + (字母?A=1..:99)`），
**开发版基线必须高于已发版本**，否则装不上。

## 四、排障速查（都是踩过的坑）

| 现象 | 原因 | 处理 |
|---|---|---|
| 位置一直"不知道" | GeoIP 未初始化 | `cd /opt/ds-gateway && npm install`；日志搜 `GeoIP 初始化失败` |
| 更新检查 404 | 通道未发布 | 跑 `publish-update.mjs` |
| 请求 400 `invalid date` | `latest_reminder` 带了时分或星期与日期不符 | 该字段只接受 `YYYY-MM-DD,<weekday>,<location>,<platform>,<language>` |
| 请求 400 `weekday does not match` | 星期算错 | `Intl.DateTimeFormat` 用本地时区生成，别手写 |
| 附件上传被拦 | CORS 未放行 PUT | 网关 `Access-Control-Allow-Methods` 必须含 PUT |
| TS 报 `String 不可调用` | proxy 内 `clientKey` 是局部字符串，遮蔽取 IP 的函数 | 用 `clientIpOf(req)` |
| 启动卡在加载页 | 初始化异常未置 `ready` | 见 `chat/store.ts` 的 catch，必须同时 `ready: true` |

**铁律**：客户端永远不能因为"某个可选信息缺失"而阻塞主界面。

## 五、安全现状

```text
DeepSeek Key   服务器不保存，用户自备（ALLOW_INSTANCE_KEY=0）
密码           scrypt(N=16384) 加盐；登录令牌只存 sha256
登录           按账号指数退避 + 审计表（IP/动作/时间，不含密码令牌）
配额           每日 token 上限（默认 200 万），来自用量账本
传输           TLS；日志脱敏（sk- 开头自动打码）
备份           本地 14 份 + 异地推送；不含任何密钥
```

**已知遗留**：无 2FA、无记忆库加密（`node:sqlite` 不支持 SQLCipher，`pragma key` 会被静默忽略）。
